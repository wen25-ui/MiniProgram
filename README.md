# 微信小程序业务返现管理系统

## 使用方式

1. 打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本项目根目录。
4. 首次导入时选择游客模式，或填写你自己的小程序 AppID。

## 成员 AppID 配置

团队成员只使用一个个人本地配置文件：`project.private.config.json`。该文件用于保存自己的微信小程序 AppID，不提交到 GitHub。

首次拉取代码后，每位成员执行一次：

1. 复制 `project.private.config.example.json` 为 `project.private.config.json`。
2. 将 `project.private.config.json` 中的 `appid` 改为自己的微信小程序 AppID。

`project.private.config.json` 已加入 `.gitignore`，后续拉取代码不会覆盖成员自己的本地配置；共享的 `project.config.json` 不包含 AppID。

## 业务闭环

客户：
填写初筛信息 → 初筛通过 → 补充资料 → 提交申请。

客服：
待审核客户 → 审核通过 → 确认预约 → 指派业务员。

业务员：
接收派单 → 开始办理 → 完成实名核实 → 提交办理凭证。

客服、财务：
客服核销凭证 → 财务登记纸面账单 → 确认返现入账与佣金账面状态。

商家：
展示本店普通推广二维码供已登录用户扫码，并查看当前门店推荐客户、办理进度、预计佣金、锁定佣金和已结算佣金。

BOSS：
查看全局经营、业务进度、返现、佣金和角色统计。

后台管理员：
增加、修改、停用商家、业务员和客服账号及其基础信息；删除采用逻辑停用，保留历史业务记录。

## 数据与服务

- 小程序通过 `services/api-client.js` 调用服务端接口。
- 本地服务位于 `server` 目录，业务数据存储在 MySQL。
- 数据库结构、迁移和演示数据分别位于 `database/schema.sql`、`database/migrations` 和 `database/seed-demo.sql`。
- `mock/users.js` 当前仅为业务员选择目录提供原型数据，员工目录接口接入后可移除。

当前调试使用普通二维码，二维码内容为服务端生成并校验的商家邀请码。它适用于用户登录小程序后调用扫码功能，不会从微信外部直接唤起小程序。项目 AppID 为 `wx993714925802691b`；切换微信官方小程序码时，AppSecret 必须通过服务端环境变量提供，禁止写入仓库或小程序代码。
