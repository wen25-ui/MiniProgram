# 系统需求说明

## 1. 文档定位

本文汇总当前已确认需求与待确认问题，是后续模块划分、基础框架和接口设计的需求基线。任何标记为“待确认”的事项均不得在实现中自行假设。

## 2. 目标与业务闭环

系统面向实体门店引流和上门业务办理，形成以下闭环：

```text
商家专属二维码
    → 用户注册、登录并进入用户端
    → 用户自助登记与自动预审
    → 公司人工复审、派单和预约上门
    → 业务员办理、提交凭证与核销
    → 纸面账单确认、订单返现完成入账记录
    → 六端按权限同步进度、查询和管理
```

## 3. 进入、注册与登录

### 已确认

- 用户只可通过商家提供的二维码扫码进入资格申请流程。
- 商家二维码只用于邀请用户，不用于邀请商家、业务员、客服、财务或 BOSS；每条申请在创建时一次性绑定二维码对应的商家，后续不可修改。
- 商家端可提供面向用户的专属二维码。
- 用户首次进入必须完成注册；当前统一采用手机号登录。微信授权是否接入保留后续确认。
- 用户首次登录成功后，直接进入小程序用户端。
- 二维码和分享链接需要保留用户来源归因，用于门店或邀请关系追踪。
- 用户输入手机号后，系统查询号码归属地；若为非本地号码，询问用户是否接受办理本地卡并记录其选择。

### 待确认

- 手机号与微信授权是否绑定为同一用户账号，以及合并规则。
- 二维码/分享链接的参数、有效期、失效、归因修改和防篡改规则。
- 用户注册的最小采集字段、隐私告知和授权文本。

## 4. 角色与账号

系统包含用户端、商家端、业务员端、客服端、财务端、BOSS 端和后台管理端。

| 角色 | 职责定位 | 账号规则 |
| --- | --- | --- |
| 用户 | 登记、预审、预约、订单和返费查询 | 从二维码或分享链接进入，首次注册后默认进入 |
| 商家 | 提供本店二维码、查看归属客户进度与佣金 | 当前暂统一采用手机号登录；开户与审核规则保留 |
| 业务员 | 接收派单、上门办理、提交凭证和核销 | 当前暂统一采用手机号登录；开户与审核规则保留 |
| 客服 | 客户服务、人工审核、派单、核销和业务协同 | 当前暂统一采用手机号登录；开户与审核规则保留 |
| 财务 | 纸面账单、返现入账确认与对账管理 | 当前暂统一采用手机号登录；开户与审核规则保留 |
| BOSS | 经营管理 | 由后台创建账号，绑定 BOSS 手机号登录；允许多个 BOSS |
| 后台管理员 | 商家与员工账号管理 | 预置或由数据库管理员创建；可维护商家、业务员和客服账号 |

后台管理员可以增加、修改、停用商家、业务员和客服的账号及基础信息。为保留订单、派单、审核和审计记录，“删除账号”统一采用逻辑停用，并立即撤销该账号的现有登录会话。

### 待确认

- 一个账号是否允许拥有多个角色，以及默认进入端和角色切换规则。
- 商家、业务员、客服、财务账号由谁创建及如何审核；登录暂统一采用手机号方式。
- 用户是否可以升级为商家、业务员或其他员工角色。
- 多个 BOSS 的数据范围、管理权限及公司/区域隔离规则。
- 客服是否包含在线咨询、工单、电话记录等辅助能力。
- 财务的纸面账单录入、复核、作废与更正权限。

## 5. 用户端需求

### 已确认

- 用户填写三项预审信息：本机手机号及是否为本地号码；非本地号码时是否接受新开卡；个人（全家）套餐档位及三年履约确认。
- 月话费档位由用户手动选择，当前提供 `<79`、`79+`、`150+`、`250+`、`400+` 五个标签；档位的完整区间边界仍需确认。
- 用户须确认三年内不销户、不转网、不降套餐，三项均须满足。
- 系统自动预审并拦截不合格客户；合格用户进入待办理池。
- 系统根据用户选择的月话费档位判定返现档位；用户端只展示预计可返现金额，不构成最终承诺。
- 用户可查看预约上门时间、自己的订单进度和返现完成入账状态。
- 需求提及六类淘汰对象，但尚未提供完整规则。

### 待确认

- 六类淘汰规则、命中提示和人工兜底流程。
- 100–5000 元返现的档位与计算规则、纸面账单确认规则。
- 预约时间、改约、取消和超时未到场规则。

## 6. 商家端需求

### 已确认

- 商家向到店客户提供本店专属二维码。
- 商家查看归属客户的预审/订单进度：待审核、待上门、办理中、已成功、返现完成入账等。
- 商家查看每单锁定的 10% 佣金明细及纸面账单对账信息。
- 商家不负责资质判断、政策解释或售后跟进。

### 待确认

- 10% 佣金的计算基数、锁定/入账确认时点，以及纸面账单更正规则。
- 商家可见客户数据的脱敏、导出和权限规则。
- 二维码创建、停用、轮换及归因变更规则。

## 7. 客服审核与业务员端需求

### 客服审核、派单与核销

- 系统自动预审后，由客服进行人工复审：本地用户/可开本地卡、运营商活动资格、近一年合约记录、欠费或逾期情况。
- 客服审核通过后，由营业厅或客服联络用户确认上门时间，并一键指派业务员；不通过则作废。
- 业务员提交凭证后，由客服完成核销；核销不通过时应退回并说明原因。

### 业务员

- 业务员仅接收审核通过且已派单的客户，查看预约时间、必要资料和返费档位。
- 业务员按已确认的上门时间办理携转或新开卡，完成实名核实后在线提交凭证并核销订单。
- 当前实名核验仅记录“已核实”结果；是否采集或保存其他资料保留后续确认。
- 合法核销后，相关角色可同步看到服务完成状态。

### 待确认

- 接单、拒单、改派、改约、超时和异常上报规则。
- 凭证类型、上传限制、审核要求、保存期限和防篡改规则。

## 8. 客服、财务与 BOSS 端需求

- 客服负责人工审核、派单和核销；在线咨询、工单、电话记录等辅助能力待定义。
- 财务端负责纸面账单、返现完成入账确认与对账；具体菜单、订单可见范围和操作权限待定义。
- BOSS 端支持多个由后台创建并绑定手机号的账号；经营看板、人员管理和数据隔离范围待定义。

## 9. 纸面账单、入账确认、同步与审计

### 已确认

- 系统不涉及资金流动，不调用支付、转账、佣金打款或退款能力；所有账单均为纸面账单。
- 办理成功后，系统记录客户 100–5000 元返现与商家 10% 佣金的应记账信息。
- “有效成单”以客服核销通过为准。
- 财务确认纸面账单后，将订单标记为“返现完成入账”；该状态仅表示账务确认，不表示系统完成资金支付。
- 六端按权限查看订单进度与账单/入账确认状态；业务员核销后的状态需及时同步。
- 订单主流程为：用户提交需求 → 提交申请 → 客服审核 → 审核通过 → 营业厅/客服联系用户 → 确认上门时间 → 上门办理 → 服务完成 → 结束。驳回、改约、派单失败和账单异常等分支仍待定义。
- 数据支持查询和导出。

### 待确认

- 订单状态机：取消、改约、派单失败、核销失败、账单异常等分支。
- 纸面账单须记录账单编号、金额、日期、门店、订单、经办人、附件和备注；录入、复核、归档、作废/更正与返现完成入账确认流程仍待定义。
- 同步机制、失败重试和人工补偿。
- 导出权限、审计日志、水印及数据保留策略。

## 10. 安全与合规前置项

- 手机号、预约信息、运营商资质、欠费信息、办理凭证和纸面账单信息按最小必要原则采集、展示和保存。
- 注册及业务办理需提供隐私告知、用途说明和授权留存。
- 审核、派单、核销、纸面账单确认和导出操作均需记录操作者、时间、原因及前后状态。
- 权限校验、金额计算、状态流转和二维码归因必须由服务端控制。

## 11. 数据可见范围

- 所有角色均可查看授权范围内订单的状态。
- 用户仅可查看本人订单。
- 商家仅可查看本店归属订单。
- 业务员和客服仅可查看本人负责订单。
- 财务与 BOSS 可查看全部订单。
- 订单字段级脱敏、导出权限和客服/财务的具体操作权限仍待定义。

## 12. 模块划分前必须确认

1. 员工角色的开户与审核方案。
2. 多角色账号和角色切换规则。
3. 客服、财务和 BOSS 的页面范围与操作权限。
4. 六类淘汰规则、月话费档位边界、返现档位、佣金基数及纸面账单/入账确认/更正规则。
5. 后端、鉴权、微信 AppID、业务域名和接口契约。
6. 个人信息、凭证和导出数据的合规及保留策略。
